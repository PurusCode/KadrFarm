# Автоматические редакторские рекомендации Discovery

## Назначение

`video-farm discover-recommend` предназначен для универсального канала без постоянной ниши. Он анализирует сохранённые `discovery.json` и `discovery.md`, формирует смысловые кластеры реальных видео и предлагает ранжированный список актуальных оригинальных тем из любых категорий, присутствующих в выборке. Ни одна категория не имеет заранее заданного преимущества.

## Источники данных

- `discovery.json` — единственный структурированный источник видео, идентификаторов, исходных счётчиков, дат публикации и происхождения в поисковой выдаче.
- `discovery.md` — парный отчёт для человека. Программа сверяет дату формирования и число видео с JSON; одинаковые записи не отправляются модели дважды.
- Обрабатываются все уникальные записи `unique_candidates`, а не только первые N видео.

## Алгоритм

1. Проверить schema 2.0, срок хранения исходных API Data и соответствие JSON/Markdown.
2. Подготовить компактные записи всех кандидатов и разбить их на пакеты.
3. LLMRouter обрабатывает пакеты по настроенному порядку PRIMARY → SECONDARY и находит смысловые группы заголовков.
4. Второй проход объединяет похожие группы и ранжирует оригинальные редакторские идеи.
5. В рекомендации попадают только реальные `video_id`, найденные в исходном отчёте; каждая тема должна иметь не менее двух видео-оснований.
6. Система отдельно считает независимые каналы, присутствие видео в поисковых окнах 24 часа/7 дней и появление в сортировках `viewCount`/`date`. Эти признаки описывают состав выдачи, а не скорость роста просмотров.
6. Программа сохраняет `recommendations.json` и `recommendations.md`.

## Что означает приоритет

Приоритет — редакторское суждение LLM по актуальности публикаций, повторяемости конкретного сюжета и независимости каналов. Универсальный канал может выпускать ролики на любую тему; фильтра по тематической нише нет. Это не официальный рейтинг YouTube и не математический трендовый балл.

`view_count` показывается как исходное поле API. Счётчики найденных уникальных видео в поисковых окнах 24 часа/7 дней и сортировках `viewCount`/`date` считаются по происхождению в отчёте. Не рассчитываются скорость прироста просмотров, нормализация по возрасту, viral score или отношения счётчиков. Анализируются заголовки и метаданные, но не содержимое самих видео; перед сценарием нужно открыть источники и проверить факты.

## Запуск

```powershell
python -m kadr_farm.cli discover-recommend
```

Параметры по умолчанию:

- JSON: `output/discovery/discovery.json`
- Markdown: `output/discovery/discovery.md`
- Результат: `output/discovery/recommendations.json` и `recommendations.md`
- Тем: до 10
- Размер пакета: 180 видео

Программа делает запросы только к настроенным LLM-провайдерам. Новые обращения к YouTube Data API не выполняются.

Рекомендации содержат YouTube API Data и наследуют исходный `refresh_or_delete_by_utc`; `discover-cleanup` удаляет их вместе с исходным отчётом по истечении срока хранения.


## Предварительный отбор перед LLM

Полный список `unique_candidates` остаётся в `discovery.json` без изменений, но не отправляется модели целиком. До создания LLMRouter модуль выполняет локальный отбор:

1. Для каждого поискового набора `(market, stream_id, window_days, order=viewCount)` выбираются до четырёх видео с наибольшим исходным `view_count`.
2. Для каждого поискового набора `(market, stream_id, window_days, order=date)` выбираются до четырёх самых свежих видео по `published_at`.
3. Повторы одного `video_id` между направлениями, окнами и сортировками объединяются.
4. Дополнительно добавляются до десяти уникальных видео из российского `mostPopular` chart, если они ещё не вошли в выборку.
5. Для российского режима при 40 поисковых наборах это даёт не более 160 уникальных видео из поиска плюс до десяти из чарта — максимум 170.

Размер LLM-пакета по умолчанию — 50 видео. Для максимальной выборки требуется не более четырёх запросов кластеризации и одного финального запроса. Новые обращения к YouTube API не выполняются.

Сортировка `viewCount` использует общий счётчик просмотров на момент сбора, а сортировка `date` — дату публикации. Это помогает сбалансировать отбор, но не измеряет скорость прироста просмотров и не доказывает тренд.

Канал универсальный: постоянной тематической ниши нет. Все категории конкурируют на равных. В JSON/Markdown сохраняется аудит выбранных поисковых наборов и список добавленных видео российского чарта.


## Производимость темы средствами KadrFarm

Каждая предварительно рекомендованная тема проходит один дополнительный LLM-аудит, который одновременно проверяет смысловую целостность видео-оснований и возможность производства средствами фермы.

**Что умеет ферма:** русская дикторская дорожка; «живая презентация»; авторские слайды; схемы, диаграммы, таблицы, карты и таймлайны; фотографии/иллюстрации; стоковый B-roll. В текущей конфигурации Pixabay настроен, Pexels не настроен.

**Что ферма не гарантирует:** собственные съёмки, интервью, репортажи, уникальные эксперименты, кадры конкретного события/человека, доступ к конкретному игровому процессу или эксклюзивным архивам. Наличие подходящего материала в фотостоке не предполагается заранее — его нужно проверить поиском.

Критически важно: весь смысловой рассказ, факты и выводы должны быть понятны из дикторской дорожки. Презентация, фотографии и видео усиливают речь и не заменяют её.

Для каждой темы формируется статус:
- `high` — готово к производству средствами фермы;
- `conditional` — можно производить после конкретной адаптации угла подачи;
- `low` — центральная ценность зависит от визуалов или действий, которых ферма не может гарантировать.

Основной рейтинг включает `high` и `conditional`. Одноканальные сюжеты остаются в наблюдении. Сюжеты без конкретного общего предмета/события или с несогласованными источниками отклоняются. Темы `low` показываются отдельно, а не смешиваются с производственными рекомендациями.

Этот аудит анализирует названия и метаданные исходных роликов. Он не подтверждает фактическое содержание исходных видео и не проверяет наличие стоковых кадров.
