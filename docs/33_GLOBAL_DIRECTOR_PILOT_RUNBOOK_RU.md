# Пилот Global Director — отдельный безопасный запуск

Статус: Stage I, изолированный пилот Pass 1. Production-конвейер не подключается.

## 1. Назначение

Пилот проверяет, способен ли выбранный провайдер построить `VisualStoryPlan` версии 1.1 для всей исходной раскадровки в рамках одной глобальной задачи Pass 1. При необходимости адаптер может выполнить дополнительные HTTP-попытки к тому же провайдеру. Автоматического перехода на другой провайдер нет. Пилот не создаёт `SceneCompositionPlan`, не синтезирует WAV, не загружает медиа и не собирает MP4.

Первый режим — `dry-run`: он проверяет входную раскадровку, строит настоящий системный и пользовательский промпты, JSON Schema и сохраняет их в `global_request_preview.json`. Сетевые обращения не выполняются.

Только флаг `--execute` разрешает выполнить глобальную задачу Pass 1 через выбранного провайдера. Число HTTP-попыток может быть больше одной, например при исправлении невалидного ответа. Автоматического переключения на другой провайдер нет.

## 2. Строгая политика провайдера

Запускатель закрепляет ровно один provider из настроек:

- по умолчанию `primary` (MWS);
- `secondary` допускается только как явно переданный выбор;
- клиентский список `StructuredLLMRouter` содержит ровно один provider, поэтому скрытого fallback нет;
- тайм-аут по умолчанию 300 секунд, конечный и изменяемый явным аргументом;
- в `ProductionJournal` закрепляются provider, model и base URL; возобновление с другой идентичностью запрещается;
- API-ключ не записывается в run context или отчёт.

## 3. Команды

Из корня `D:\my_projects\KadrFarm` сначала проверить входные данные без обращения к MWS:

```powershell
python -m kadr_farm.visual_story_global_pilot `
  --storyboard .\output\story_test\director_pilot\storyboard_draft.json `
  --out .\output\visual_story_global_pilot_20261119
```

Ожидается `mode=dry_run`, `llm_called=false`, количество сцен, provider/model, длина промпта в символах и байтах, путь `global_request_preview.json`.

Промпт-превью содержит полный текст сценария. Оно сохраняется только в `output/` (не добавлять в Git) и предназначено для локального анализа.

Перед реальным вызовом проверь:

1. ожидаемое число сцен и отсутствие пропусков/дубликатов;
2. выбран `primary`, если не было отдельного осознанного решения;
3. модель и endpoint соответствуют ожидаемой конфигурации MWS;
4. каталог пилота не используется другим запуском;
5. размер промпта и схема выглядят разумно.

Только после проверки выполнить тот же вызов с флагом:

```powershell
python -m kadr_farm.visual_story_global_pilot `
  --storyboard .\output\story_test\director_pilot\storyboard_draft.json `
  --out .\output\visual_story_global_pilot_20261119 `
  --provider primary `
  --timeout-seconds 300 `
  --max-tokens 8500 `
  --execute
```

Не запускать повторно в другом output-каталоге при сетевой ошибке: для восстановления используется тот же `--out`.

## 4. Артефакты

```text
output/visual_story_global_pilot_20261119/
├── global_request_preview.json       # только dry-run: промпт + schema
├── visual_story_plan.json            # прошедший Pydantic и global validation план
├── visual_story_global_report.json   # сводка; human_review_required=true
└── recovery/
    ├── production_state.json
    ├── model_calls/
    └── llm_results/
```

Успешное завершение означает только структурную и заданную глобальную редакторскую валидацию. Оно не означает, что человек одобрил творческое решение или факты. Перед Pass 2 Global Plan нужно отдельно прочитать и оценить.

## 5. Проверка качества после вызова

Оценивать не только валидность JSON. Редактор должен проверить:

- визуальная идея действительно объединяет весь ролик и не подменяет тему ролика;
- роли сцен соответствуют их речи;
- возвращающиеся мотивы используются содержательно, а не для галочки;
- сюжетная связность не превращается в искусственное повторение одного объекта;
- визуальные повороты совпадают со смысловыми поворотами дикторского рассказа;
- модель не придумала события, бренды, факты или числа;
- заключение визуально разрешает поставленный в начале вопрос.

Если план формально проходит, но творчески слаб, не ослаблять validator и не начинать Pass 2. Исправить редакторский промпт/контракт, повысить версию prompt и повторить задачу с корректным fingerprint.

## 6. Граница Stage I

Пилот не импортируется из `production_director.py`. Интеграция возможна только после ручной оценки Global Plan и отдельного успешного пилота Scene Director на нескольких последовательных сценах.

## 7. Защита от параллельного запуска

При любом режиме запускатель удерживает эксклюзивную межпроцессную блокировку
файла `.global_director_pilot.lock` в каталоге результата. Блокировка действует
во время записи preview, проверки журнала, восстановления, запросов к модели
и записи итоговых артефактов.

Второй процесс с тем же `--out` ожидает освобождения блокировки. Ожидание
ограничено 3600 секундами. Если каталог не освободился за это время, второй
запуск завершится с `TimeoutError`, не изменяя журнал восстановления.

Блокировка применяется и к dry-run, поскольку он записывает
`global_request_preview.json`. Не удаляйте файл блокировки во время работающего
процесса.

## 8. Интеграционная проверка маршрутизатора и журнала

`tests/test_global_director_journal_integration.py` использует настоящий
`StructuredLLMRouter` и `ProductionJournal`, но подменяет сетевой клиент
детерминированной тестовой реализацией. Проверяются запись исходного и
исправленного ответа, успешный checkpoint и его повторное использование
после создания нового экземпляра журнала. Внешние HTTP-запросы не выполняются.

Дополнительный тест запускает два отдельных процесса и проверяет, что второй
не может войти в общий каталог, пока первый удерживает блокировку.
